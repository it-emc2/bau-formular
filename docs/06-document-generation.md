# Document Generation

## Overview

bau-formular generates two types of documents:
1. **Confirmation Letter** (Bestätigungsschreiben) — HTML/Word document confirming successful completion
2. **Step Documents** (Schrittdokumente) — PDF files summarizing each inspection step

Additionally, it can proxy **Arbeitsbericht (Work Report)** PDF generation from an external service.

## Confirmation Letter

Generated by `services/documentLetter.js`.

### Content Structure

The letter follows a formal German business letter format:

```
[Customer Name]
[Street Address]
[Address Line 2]
[PLZ City]

[City], im [Month Year]

Sehr geehrte Damen und Herren,

hiermit bestätige ich den durch die Fa. EmC2 [erfolgreich] durchgeführten
[barrierearmen Umbau / Nachbesserung / Serviceeinsatz] [gemäß Auftrag {orderNumber}]
mit Hilfe der mir genehmigten Förderung nach §40 SGB XI Abs. 4.

Mit freundlichen Grüßen

[Customer Signature Image]
[Customer Name]
```

### Dynamic Content

The letter text adapts based on:
- **Appointment type** (`artDesTermins`):
  - `Umbau` → "barrierearmen Umbau"
  - `Nachbesserung` → "Nachbesserung"
  - `Service` → "Serviceeinsatz"
- **Completion status** (`terminStatus`):
  - `Erfolgreich beendet` → "erfolgreich durchgeführten"
  - `Nicht erfolgreich beendet` → "durchgeführten" (no "erfolgreich")
- **Order number**: included as "gemäß Auftrag {number}" if present
- **Reference date**: uses the first available from: `unterschriftZeitpunkt`, `abgeschlossenAm`, `maengelAbgeschlossenAm`, `nachbesserungAbgeschlossenAm`, `unterschriftMonteurDatum`, or current date

### Output Formats

`buildDocumentPackage(data)` returns:

```javascript
{
  title: "Bestaetigung erfolgreicher Umbau",
  subject: "Bestaetigung Umbau {orderNumber or customerName}",
  fileName: "bestaetigung-{customer-slug}.doc",
  html: "<!DOCTYPE html>...",  // Full HTML document with inline CSS
  text: "Plain text version"
}
```

- **HTML**: A styled A4-page layout with Times New Roman font, suitable for print. Includes the customer's signature as an embedded base64 PNG image. The HTML is also used as a `.doc` attachment (MS Word can render HTML).
- **Text**: Plain text version used for email body and Bitrix timeline comments.
- **File name**: Sanitized customer name or order number, e.g., `bestaetigung-max-mustermann.doc`

### Customer Name Logic

```
If anrede === 'Familie' && nachname → "Familie {nachname}"
Else → "{vorname} {nachname}" or fallback to {name}
```

### HTML Styling

The letter HTML includes embedded CSS for:
- A4 page layout (`210mm × 297mm`)
- Print media query for clean printing
- Signature image sizing (max 240px × 90px)
- Footer with creation date and "emc2 Bauformular" branding

## Step Documents (PDFs)

Generated by `services/stepDocuments.js` using the `pdf-lib` library.

### PDF Structure

Each step PDF has:
- **Title** (18pt, bold) — step name
- **Subtitle** (11pt, gray) — customer name
- **Content lines** (11pt) — key-value pairs from form data
- **Signature** (if present) — embedded PNG image
- **Footer** — "Erstellt am {date}"

### Generated Documents

| # | Title | Content | Signature | Condition |
|---|-------|---------|-----------|-----------|
| 01 | Abschluss der Baustelle | Termin-ID, appointment type, status, order number, customer, address | — | Always |
| 02 | Warenprüfung vor Baubeginn | Inspection date, goods statuses (I.O. / Nicht I.O.), comments | `unterschriftWarenpruefung` | Always |
| 03 | Fotos und Video | File counts for each upload field | — | Always |
| 04 | Weitere Bilder | File counts for additional image fields | — | Always |
| 05 | Abschluss und Unterschrift | Completion date, all-work-done status, incomplete work description | `unterschriftKunde` | Always |
| 06 | Checkliste {variant} | Completed checklist items, free grab rail comment, additional notes, date | `unterschriftMonteur1` or `unterschriftMonteur2` | Always |
| 07* | Mängelbeseitigung | Completion date | `unterschriftMaengel` | Debug mode only |
| 08 | Einwilligung zur Abrechnung | Customer name, address, date of birth, billing consent signature | `unterschriftEinwilligung` | Only when `unterschriftEinwilligung` is present |

Document 07 is only generated when `includeDebug` is true (set when `debugMode` is `"true"` in the form data).

### Checklist Variant Detection

The checklist document title adapts based on the `auszufuehrendeTaetigkeiten` or `bitrixExecutionActivities` field:

```javascript
// services/stepDocuments.js → getChecklistVariant()
Source value normalized to lowercase, diacritics removed:
  Contains "handlaufe" → 06-Checkliste-Handlaeufe
  Contains "badewannenture" or "badewannentur" → 06-Checkliste-Badewannentuer
  Default → 06-Checkliste-Badumbau
```

### PDF File Naming

All PDFs follow the pattern: `{NN}-{title-slug}-{customer-slug}.pdf`

Example: `02-warenpruefung-max-mustermann.pdf`

### Signature Embedding

Signatures stored as base64 PNG data URLs are embedded into PDFs:
1. Extract base64 payload (split on comma, take second part)
2. `pdfDoc.embedPng(Buffer.from(base64, 'base64'))`
3. Scale to max 180×70px maintaining aspect ratio
4. Draw "Unterschrift:" label followed by the signature image

## Arbeitsbericht (Work Report)

The Arbeitsbericht is generated by an **external service** (Angebotskonfigurator). bau-formular provides:

### Backend Proxy

`POST /api/form/arbeitsbericht/pdf` proxies requests to the external service:
- Default endpoint: `https://angebotskonfigurator-emc2-v2.fly.dev/api/arbeitsbericht/pdf`
- Configurable via `ARBEITSBERICHT_PDF_URL` env var
- Passes the request payload through, returns the PDF binary response

### Frontend Flow

1. User searches for an offer/draft in the external system (Step 9)
2. `searchArbeitsberichtRecords()` calls external search API directly from the browser
3. User selects a result → `downloadArbeitsberichtPdf(item)`
4. Frontend fetches the full offer/draft detail from external API
5. Frontend sends the payload directly to the external Arbeitsbericht PDF endpoint
6. PDF is displayed in an iframe preview and auto-downloaded

Note: The frontend calls the external API directly (not through the backend proxy), because the Arbeitsbericht step is a dev-only feature and the external service allows CORS from the bau-formular origin.
